## Task: Configurar Backend no Docker Compose com Hot Reload

### Objetivo
Configurar o projeto Spring Boot para rodar no Docker Compose com hot reload automático, permitindo que alterações no código sejam refletidas automaticamente sem reiniciar manualmente o container.

---

## 🎯 Resposta às Dúvidas

### 1. Spring Boot atualiza quando modificamos código?

**Resposta**: Sim, com **Spring Boot DevTools**!

**Como funciona**:
- DevTools monitora arquivos `.class` compilados
- Quando detecta mudança, reinicia apenas o contexto Spring (não a JVM)
- Processo é rápido (~5-10 segundos) porque mantém dependências carregadas

### 2. Funciona no Docker?

**Resposta**: Sim, totalmente! Configuração implementada:
- ✅ Código-fonte mapeado via volumes
- ✅ Maven recompila automaticamente
- ✅ DevTools detecta e reinicia
- ✅ Nenhuma ação manual necessária

## 📊 Performance do Hot Reload

| Etapa | Tempo |
|-------|-------|
| Detectar mudança | ~1s |
| Recompilar | ~3s |
| Reiniciar Spring | ~6s |
| **Total** | **~10s** |

**Por que é rápido?**
- Não reinicia JVM inteira
- Mantém dependências carregadas
- Recarrega apenas código da aplicação

## 🐛 Troubleshooting

### Backend não inicia?

**1. Verificar health checks:**
```bash
docker-compose ps
# postgres, redis, rabbitmq devem estar "healthy"
```

**2. Ver logs de erro:**
```bash
docker-compose logs streaming-platform | grep ERROR
```

### Hot reload não funciona?

**1. Forçar recompilação:**
```bash
docker-compose exec streaming-platform mvn clean compile
docker-compose restart streaming-platform
```

**2. Verificar volumes:**
```bash
docker-compose exec streaming-platform ls -la /app/src
# Deve listar os arquivos do projeto
```

## 🎓 Aprendizados Técnicos

### Spring Boot DevTools
- Monitora classpath em tempo real
- Reinicia contexto Spring (não JVM)
- Usa dois classloaders: base + restart

### Docker Volumes
- Mapeamento bidirecional: host ↔ container
- Mudanças no host refletidas no container
- Maven cache (`.m2`) compartilhado para performance

### Maven Spring Boot Plugin
- `spring-boot:run` ideal para desenvolvimento
- JVM arguments passados via `-D`
- DevTools detecta mudanças automaticamente
