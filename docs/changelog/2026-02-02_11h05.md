## 🎯 Arquitetura Implementada

### Clean Architecture em 3 Camadas

**1. Core (Domínio)** - Regras de negócio puras
- entities/ - Entidades de domínio (POJOs)
- exceptions/ - Exceções de domínio
- repositories/ - Interfaces de repositório
- usecases/ - Interfaces de casos de uso
- dtos/ - DTOs de domínio

**2. Application (Casos de Uso)** - Orquestração
- services/ - Implementação dos use cases

**3. Infrastructure (Infraestrutura)** - Adapters
- config/ - Configurações específicas
- database/jpa/ - Persistência (entities, repositories, mappers)
- http/ - REST API (controllers, requests, presenters, handlers)
- ws/ - WebSocket (controllers)
- messaging/ - Message broker (listeners) [consumer domain]
- collectors/ - Coletores de métricas [metrics domain]

## 🎓 Princípios Aplicados

### 1. Clean Architecture (Robert C. Martin)
- Core independente de frameworks
- Regras de negócio testáveis isoladamente
- Inversão de dependência

### 2. Domain-Driven Design (DDD)
- Domains bem definidos (stream, consumer, metrics)
- Entidades de domínio com comportamento
- Repositórios como abstrações

### 3. SOLID
- **S**ingle Responsibility: Cada camada tem responsabilidade única
- **O**pen/Closed: Extensível via interfaces
- **L**iskov Substitution: Interfaces intercambiáveis
- **I**nterface Segregation: Interfaces pequenas e focadas
- **D**ependency Inversion: Core depende de abstrações

### 4. Separation of Concerns
- HTTP separado de lógica de negócio
- Persistência separada de domínio
- Configuração separada de código

## 🔄 Fluxo de Dependência

```
┌──────────────────────────────────────────┐
│      INFRASTRUCTURE LAYER                │
│  (Spring, JPA, Controllers, Config)      │
│              depende de ↓                │
├──────────────────────────────────────────┤
│      APPLICATION LAYER                   │
│      (Services, Use Cases)               │
│              depende de ↓                │
├──────────────────────────────────────────┤
│         CORE LAYER                       │
│  (Entities, Interfaces, DTOs)            │
│      (Java Puro - Zero deps)             │
└──────────────────────────────────────────┘
```

**Regra de Ouro**: Camadas externas dependem de camadas internas, NUNCA o contrário!

## 🎯 Pontos de Atenção

### ⚠️ Regras Obrigatórias

1. **Core NUNCA importa de Application ou Infrastructure**
   ```java
   // ❌ ERRADO em core/
   import org.springframework.stereotype.Service;
   
   // ✅ CORRETO em core/
   import java.util.UUID;
   import java.time.LocalDateTime;
   ```

2. **Application importa apenas Core**
   ```java
   // ✅ Pode importar
   import com.tcc.streaming.stream.core.entities.Stream;
   import com.tcc.streaming.stream.core.repositories.StreamRepository;
   ```

3. **Infrastructure pode importar tudo**
   ```java
   // ✅ Pode importar
   import org.springframework.stereotype.Repository;
   import com.tcc.streaming.stream.core.entities.Stream;
   import com.tcc.streaming.stream.application.services.StreamService;
   ```

4. **Sempre usar Mappers entre camadas**
   ```java
   // ❌ ERRADO - Não retornar JPA entity no controller
   return streamJpaRepository.findById(id);
   
   // ✅ CORRETO - Sempre mapear
   return streamJpaRepository.findById(id)
       .map(mapper::toDomain);
   ```
