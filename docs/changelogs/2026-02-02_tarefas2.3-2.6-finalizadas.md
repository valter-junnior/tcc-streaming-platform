**Implementação em StreamService.java**:

```java
@Override
@Cacheable(value = "streamStatus", key = "#id")
@Transactional(readOnly = true)
public StreamStatusDto getStatus(UUID id) {
    Stream stream = streamRepository.findById(id)
        .orElseThrow(() -> new StreamNotFoundException(id));
    
    return new StreamStatusDto(
        stream.getId(),
        stream.getStatus(),
        stream.getCurrentViewers(),
        stream.getViewersPeak(),
        stream.getWatchUrl()
    );
}
```

#### Arquivos Modificados (3):

**StreamController.java** - Novo endpoint
```java
@GetMapping("/{id}/status")
@Operation(
    summary = "Buscar status da stream",
    description = "Retorna o status atual da stream e contador de viewers (dados cacheados)"
)
@ApiResponses(value = {
    @ApiResponse(responseCode = "200", description = "Status obtido com sucesso",
        content = @Content(schema = @Schema(implementation = StreamStatusPresenter.class))),
    @ApiResponse(responseCode = "404", description = "Stream não encontrada")
})
public ResponseEntity<StreamStatusPresenter> getStreamStatus(
    @Parameter(description = "ID único da stream (UUID)")
    @PathVariable UUID id) {
    var result = getStreamStatusUseCase.getStatus(id);
    return ResponseEntity.ok(StreamStatusPresenter.from(result));
}
```

**RedisConfig.java** - Nova configuração de cache
```java
// Configuração específica para streamStatus com TTL menor (1 minuto)
RedisCacheConfiguration statusConfig = RedisCacheConfiguration.defaultCacheConfig()
    .entryTtl(Duration.ofMinutes(1))
    .serializeKeysWith(...)
    .serializeValuesWith(...);

return RedisCacheManager.builder(connectionFactory)
    .cacheDefaults(defaultConfig)
    .withCacheConfiguration("streamStatus", statusConfig)
    .build();
```

**Diferença de TTL**:
- `streams`: 10 minutos (dados completos da stream)
- `streamStatus`: 1 minuto (dados que mudam frequentemente - viewers, status)

## 🔧 Decisões Técnicas

### Por que TTL diferente para streamStatus?
- **Problema**: Status e viewers mudam frequentemente durante transmissão
- **Solução**: TTL de 1 minuto para dados mais atualizados
- **Trade-off**: Mais requisições ao banco vs. dados mais frescos

### Por que método `getStatus()` e não `execute()`?
- **Problema**: Conflito de assinatura com `GetStreamUseCase.execute(UUID)`
- **Solução**: Método específico `getStatus()` para diferenciar
- **Benefício**: Código mais claro e sem ambiguidade

### Por que perfis no mesmo arquivo application.yml?
- **Alternativa**: Arquivos separados (application-dev.yml, application-prod.yml)
- **Escolha**: Arquivo único com separação `---`
- **Motivo**: Projeto pequeno, mais fácil manter configurações centralizadas
