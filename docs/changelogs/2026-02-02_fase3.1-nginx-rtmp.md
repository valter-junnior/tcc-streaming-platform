## Objetivo

Implementar a infraestrutura de ingestão RTMP usando Nginx-RTMP com arquitetura limpa e abstração que permite futuras alternativas tecnológicas (como SRS).

## Alterações Implementadas

### 1. Abstração RTMP (Clean Architecture)

**Arquivos criados**:
- `common/rtmp/RtmpServerGateway.java` - Interface para abstração do servidor RTMP
- `common/rtmp/RtmpServerConfig.java` - Configuração do servidor RTMP
- `common/rtmp/RtmpServerProperties.java` - Properties para configuração via application.yml
- `common/rtmp/nginx/NginxRtmpGateway.java` - Implementação Nginx-RTMP

**Funcionalidades**:
- Interface `RtmpServerGateway` define contratos independentes de implementação
- Permite trocar de Nginx-RTMP para SRS apenas alterando `streaming.rtmp.provider` no application.yml
- `@ConditionalOnProperty` garante que apenas a implementação configurada seja carregada
- Health check do servidor RTMP via socket connection

### 2. Container Nginx-RTMP

**Arquivos criados**:
- `docker/nginx-rtmp/Dockerfile` - Build do Nginx com módulo RTMP
- `docker/nginx-rtmp/nginx.conf` - Configuração completa do servidor

**Características**:
- Nginx 1.24.0 compilado com nginx-rtmp-module
- Callbacks HTTP para autenticação:
  - `on_publish` → valida stream key
  - `on_publish_done` → atualiza status para LIVE
  - `on_done` → atualiza status para ENDED
- HLS output habilitado:
  - Fragmentos de 6 segundos
  - Playlist de 60 segundos
  - Pasta: `/tmp/hls`
- Servidor HTTP na porta 8081 para servir HLS e stats
- Endpoint `/stat` para estatísticas RTMP
- CORS habilitado para playback HLS

### 3. Integração Docker Compose

**Alterações em `docker-compose.yml`**:
- Adicionado serviço `nginx-rtmp`
- Volume compartilhado `hls-data` para segmentos HLS
- Portas expostas: 1935 (RTMP) e 8081 (HLS)
- Dependência do `streaming-platform` para callbacks

**Alterações em `.env`**:
- `RTMP_PORT=1935`
- `HLS_PORT=8081`

### 4. Configuração Backend

**Alterações em `application.yml`**:
```yaml
streaming:
  rtmp:
    provider: nginx-rtmp  # ou "srs" no futuro
    host: ${RTMP_HOST:nginx-rtmp}
    port: ${RTMP_PORT:1935}
    application: live
    callbackUrl: http://streaming-platform:8080/api/streams/callback
```

**Integração no `StreamService`**:
- Injeção de `RtmpServerGateway` via construtor
- Uso de `rtmpServerGateway.getServerConfig()` para obter URL RTMP dinâmico

## Decisões Técnicas

### Por que Arquitetura com Gateway?
Permite comparação de tecnologias (objetivo do TCC) sem reescrever código:
- Trocar de Nginx-RTMP para SRS requer apenas:
  1. Criar `SrsRtmpGateway implements RtmpServerGateway`
  2. Alterar `streaming.rtmp.provider=srs` no application.yml

### Por que Callbacks HTTP?
- Validação centralizada no backend (single source of truth)
- Permite logging e auditoria de tentativas de streaming
- Integração com lógica de negócio (publicar eventos no RabbitMQ)

### Por que HLS no mesmo container?
- Simplifica arquitetura inicial
- Nginx já tem suporte nativo para servir arquivos estáticos
- Pode ser separado depois se necessário
